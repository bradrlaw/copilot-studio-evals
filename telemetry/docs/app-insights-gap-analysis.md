# App Insights Gap Analysis — GenAI Observability

What the KQL query set in `../queries/genai_observability_queries.kql` **can** and
**cannot** tell us when the only telemetry sink is **Application Insights**, across
the two agent/model platforms in scope:

- **A — Azure AI Foundry** models & agents (OpenTelemetry GenAI semantic conventions)
- **B — Microsoft Copilot Studio** agents (environment-level OTel *and* legacy agent-level)

> 📝 **Note:** Verify the schema against current Microsoft documentation, the
> relevant SDK version, and Query 0 results from your own environment before
> relying on these mappings.

---

## 1. Executive summary

| Capability (our 5 queries) | AI Foundry | Copilot Studio |
| --- | :---: | :---: |
| Tool invocation frequency & error rate | ✅ | ✅ |
| Tool latency p50/p95/p99 | ✅ | ✅ |
| Token usage by model | ✅ | ❌ **not logged** |
| Estimated cost per conversation | ✅ | ❌ **not logged** |
| Top-10 most expensive conversations | ✅ | ❌ **not logged** |

> ⚠️ **Warning:** The headline gap is **cost & token accounting for Copilot
> Studio**. Copilot Studio emits **no token counts** to App Insights (or to
> Dataverse) on any documented path, so Queries 2, 4, and 5 return **zero rows**
> for Copilot Studio traffic.

---

## 2. What App Insights gives us — by source

### 2A. Azure AI Foundry (OTel GenAI) — the complete picture

All spans land in the **`dependencies`** table with `gen_ai.*` custom dimensions.

| Signal | Field | Notes |
| --- | --- | --- |
| Model | `customDimensions["gen_ai.response.model"]` / `["gen_ai.request.model"]` | Response model may carry a version suffix; the cost queries collapse it to a price key. |
| Input tokens | `customDimensions["gen_ai.usage.input_tokens"]` | Populated from the provider's `prompt_tokens`. |
| Output tokens | `customDimensions["gen_ai.usage.output_tokens"]` | From `completion_tokens`. |
| Total tokens | — | **Not emitted**; derived as input + output. |
| Tool name | `customDimensions["gen_ai.tool.name"]` | On `execute_tool {tool}` spans. |
| Conversation | `customDimensions["gen_ai.conversation.id"]` → `["gen_ai.thread.id"]` → `operation_Id` | Cost queries coalesce in that order. |
| Latency | `duration` column (ms) | |
| Success | `success` column + `resultCode` | |

> 💡 **Tip:** Confirm the discriminator in *your* instance with Query 0. The
> `gen_ai.system` value is `az.ai.inference` (inference SDK), `az.ai.agents`
> (agents SDK), or `openai` (vanilla OpenAI SDK + the `openai-v2` instrumentor).

### 2B. Copilot Studio — two paths, neither with tokens

**Environment-level (preview, OTel-aligned)** → `dependencies`, `type == "GenAI"`,
`name in ("InvokeAgent","ExecuteTool","OutputMessages")`:

- ✅ Tool name (`gen_ai.tool.name`), latency (`duration`), success (`success`/`resultCode`)
- ✅ Conversation id (`gen_ai.conversation.id`), agent id/name, model **name** (`gen_ai.request.model`)
- ❌ **No `gen_ai.usage.*` token fields**

**Agent-level (classic Bot Framework)** → `customEvents`
(`BotMessageReceived` / `BotMessageSend`), plus an optional legacy MCP path
(`dependencies | where name == "mcp.tool"`, with provider-specific custom
dimensions for tool name and outcome):

- ✅ Conversation transcript text (only if *Log conversation details* is enabled), tool name/outcome/latency (MCP path)
- ❌ No token counts, no model attribution

## 3. The gaps, ranked

### Gap 1 — No Copilot Studio token/cost telemetry (highest impact)
Copilot Studio does not record input/output tokens anywhere queryable
(App Insights **or** Dataverse). Root cause: Copilot Studio is billed per
message/session (Copilot Studio capacity), not per token, so token accounting
isn't surfaced.

> 📝 **Note — mitigations:**
> - **Message-based proxy:** count `OutputMessages` / billed messages per
>   conversation as a *volume* proxy, and track spend via the **Copilot Studio
>   capacity / billing** reports in the Power Platform Admin Center (tenant-level,
>   not per-conversation).
> - **Move inference to AI Foundry:** where an answer is generated by a model you
>   own in AI Foundry (e.g. a custom model/MCP tool the agent calls), that hop
>   *does* emit tokens — instrument those components and join on conversation id.
> - **Estimate:** approximate tokens from transcript text length (chars ≈ tokens×4)
>   as a rough, clearly-labelled estimate only.

### Gap 2 — `gen_ai.system` is being deprecated
The OTel spec is replacing `gen_ai.system` with `gen_ai.provider.name`. Azure
SDKs still emit `gen_ai.system` today. Queries key off `gen_ai.system` and the
Copilot `resource.provider` value; revisit if a future SDK switches.

### Gap 3 — Reasoning tokens not itemised
For o1/o3 models, reasoning tokens are folded into output tokens and are not
separately emitted (`gen_ai.usage.reasoning.output_tokens` is spec-only). Cost is
approximately correct (reasoning bills at the output rate) but not itemised.

### Gap 4 — Pricing is not in telemetry
Cost requires a maintained price list. The datatable in Queries 4/5 is a mid-2025
snapshot and **must be verified** against the live Azure OpenAI pricing page;
regional/PTU deployments differ.

### Gap 5 — Conversation id is not uniform
AI Foundry may use `gen_ai.conversation.id`, `gen_ai.thread.id`, or only
`operation_Id`; Copilot Studio uses `gen_ai.conversation.id` (env) or
`customDimensions["conversationId"]` (agent). Cross-source joins on a single
conversation key are therefore unreliable.

## 4. Where Dataverse fills gaps (Copilot Studio only)

Some Copilot Studio data lives in **Dataverse**, not App Insights:

| Data | Dataverse location | In App Insights? |
| --- | --- | --- |
| Full conversation transcripts (message text, tool calls, topic redirects) | `ConversationTranscript` | Partial (text only if logging enabled) |
| Session outcome (Resolved/Escalated/Abandoned), turn count | `ConversationTranscript.Content` → `SessionInfo` | ❌ |
| Node-level execution trace | `ConversationTranscript.Content` → `nodeTraceData` (Enhanced Transcripts) | ❌ |
| **Token counts / model cost** | **Nowhere** | ❌ |

> ⚠️ **Warning:** Dataverse does **not** close the token/cost gap — transcripts
> exist, token counts do not. Default `ConversationTranscript` retention is ~30
> days.

---

## 5. Recommendations

1. **Split reporting by platform.** Present AI Foundry cost/token dashboards fully;
   for Copilot Studio, present volume + latency + error rate and label cost as
   "not available from App Insights."
2. **Run Query 0 first** in any new environment to confirm which sources and
   `gen_ai.system` values are present before trusting Queries 1–5.
3. **Keep the pricing datatable current** and dated; treat cost as an estimate.
4. **Instrument owned model hops in AI Foundry** so at least those emit tokens,
   and standardise on a single conversation id attribute where you control it.
5. **For true Copilot Studio cost**, use Power Platform capacity/billing reports
   as the system of record; App Insights is for behaviour, not spend.
